# NXOS — Nexa Operating Layer

The long-term (20-year) vision volume: an AI coordination layer that sits above existing operating systems (Windows, macOS, Linux, Android, iOS, and future systems) rather than replacing any of them. Written as its own numbered series, `NLB-NXOS-*`, per `NLB-00` Article VII, occupying a single reserved slot — Volume 23 — in the Bible's top-level roadmap.

Part 1 named four "fabrics" (Context, Knowledge, Memory, Workflow) plus the Universal Goal Engine. Parts 2–6 formalize each in depth — none of them introduce a second, competing mechanism; each explicitly builds on the platform volume that already owns the underlying capability.

## Why five proposed "volumes" became four parts of one series

Batch 7 (as proposed) would have created Volumes 30–34 as independent top-level documents. Each, however, maps almost one-to-one onto a fabric NXOS Part 1 had just named — Cognitive Architecture is the Goal Engine's mechanism, Memory System is the Memory Fabric, Knowledge Graph is the Knowledge Fabric, Hyper Automation is the Workflow Fabric. Publishing them as separate top-level volumes would have put the same ideas (memory layering, specialist registration, the connected graph, cross-domain automation) in two places under two names. Folding them into `NLB-NXOS-002`–`006` keeps NXOS's own map accurate and avoids the Bible re-deriving concepts `NLB-06`, `NLB-07`, `NLB-09`, `NLB-10`, `NLB-21`, and the NIC series already established.
